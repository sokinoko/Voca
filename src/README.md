# src — 데이터 소스와 적용 스크립트

이 앱은 **빌드 파이프라인이 없다.** 저장소 루트의 `index.html` 한 파일이
소스이자 산출물이고, 모든 데이터는 그 안의 `const DB = {...}` 리터럴에 들어 있다.

예전에 파이썬 빌드 파이프라인이 있었지만 작업 컨테이너가 초기화되면서
**소스가 통째로 사라졌다.** 산출물만 남아 데이터를 역추출해야 했다.
이 폴더는 같은 일이 다시 일어나지 않게 하려고 있다.
부록 데이터와 직접 쓴 시험 문항은 여기 파이썬 모듈이 원본이다.

## 폴더

```
src/
  data/       손으로 쓴 원본 데이터 (여기를 고친다)
  apply/      data/를 읽어 index.html의 DB에 넣는 스크립트
  check.js    index.html 한 파일을 검사한다 (의존성 없음)
  test/       브라우저 회귀 (playwright 필요)
```

### test/

```bash
node src/check.js          # 의존성 없음. 데이터와 문항 생성기를 검사한다
npm i playwright           # 아래는 크로미움이 필요하다
bash src/test/run.sh       # 브라우저 회귀 전부
node src/test/pwdark.js    # 하나만
```

글자 크기 배율이 모바일 재정의에 막혀 안 먹던 것.

### tools/

평가원 PDF에서 단어를 뽑는 도구다. 시험이 하나 더 올 때마다 쓴다.

```bash
python3 src/tools/wp_extract.py <해설지.pdf>      # [Words and Phrases]를 문항별로
python3 src/tools/pdftext.py   <시험지.pdf> out.txt  # 낱말 안 공백을 되돌린 본문
python3 src/tools/verify_src.py "26 9모" <대본.pdf> <시험지.pdf>   # 예문이 정말 그 문항에 있는가
```

시험을 하나 넣고 나면 **반드시 `verify_src.py`를 돌린다.** 예문을 다듬다가
본문에 없는 말이 섞여 들어가거나 문항 번호가 어긋나는 일이 실제로 있었다
(26 6모 첫 묶음에서 13곳).

`pdftext.question_spans()`로 본문을 문항별로 가른다. 예문은 **그 낱말의 뜻이 실린
문항의 지문에서만** 가져온다(묶음 문항은 그 묶음 안에서). 그래야 출처가 맞는다.

**모든 스크립트는 몇 번을 돌려도 결과가 같다.** 이미 들어가 있으면 건너뛰거나
같은 값으로 덮어쓴다. 문장을 더 쓰고 싶으면 `data/`의 해당 파일에 줄을 보탠 뒤
그 스크립트를 다시 돌리면 된다.

## 절대 지킬 것

1. **`index.html`을 손으로 편집하지 않는다.** `apply/_db.py`로 읽어서 고치고 다시 쓴다.
2. **기존 항목의 `d`(Day)를 재배정하지 않는다.** 외우던 묶음이 전부 뒤섞인다.
   새 항목만 맨 뒤 Day에 붙인다.
3. **저장 키는 단어 문자열(`w.toLowerCase()`)이다.** 인덱스 기준으로 되돌리면
   데이터를 추가할 때마다 사용자 기록이 날아간다. 예전에 실제로 그랬다.
4. **출처를 지어내지 않는다.** 기출 번호를 확인할 수 없으면 `추가`로 둔다
   (화면에는 「본시험 대비」로 나온다).
5. **본문에 줄바꿈을 넣지 않고 곧은 따옴표만 쓴다.**
6. **또 나온 낱말은 새 항목을 만들지 않고 예문을 하나 더 단다.** 뜻이 다르게
   쓰였으면 뜻도 보탠다. 같은 낱말을 두 항목으로 쪼개면 외울 것만 늘어난다.
7. **출처 라벨의 학년도를 헷갈리지 않는다.** 형석이가 칠 시험이 2027학년도 수능이라
   아직 안 쳤다. 그래서 단어장의 6월·9월 모의평가는 `27 6모` `27 9모`지만
   수능 기출은 직전 시험인 `26 수능`(2025년 11월)이다. 작년 모의평가는 `26 6모` `26 9모`.
   화면 필터는 시험 순서대로 둔다: `26 6모 · 26 9모 · 26 수능 · 27 6모 · 27 9모`.

`apply/_db.py`의 `check()`가 1·2·3을 쓰기 직전에 검사하고,
`tools/verify_src.py`가 4를 검사한다. 통과 못 하면 저장되지 않는다.

## 시험 문항이 만들어지는 방식

부록마다 성격이 달라 생성기를 따로 뒀다. 그룹의 `f` 값이 어느 것을 쓸지 정한다.

| `f` | 어디에 | 무엇을 묻나 |
|---|---|---|
| `connall` | **접속사 통합**(별도 유닛) | 지문을 읽고 빈칸에 알맞은 연결사 + 방향 판정 |
| `conn` | 연결사 10묶음 | **개념 시험 없음.** 단어 시험만. 통합 시험으로 보낸다 |
| `syn` | 정도·강조, 전치사 덩어리, 태도, 뉘앙스 | 밑줄 친 말과 뜻이 가장 가까운 것 (5지선다) |
| `pair` | 혼동 어휘 | 한 문장에 함께 나온 두세 단어를 서로 바꿔 넣기 |
| `vprep` | 전치사에 유의할 동사 | 동사가 아니라 뒤에 붙는 전치사를 빈칸으로 |
| `neg` | 부정어구 | 긍정이냐 부정이냐 판정 + 동의어 |
| `form` | 준동사 | 직접 쓴 문항만 |
| `prep` | 전치사 감각 지도 | 이 문장에서 그 전치사가 어느 용법인지 |
| `as` | as 정리 | 이 문장의 as가 어느 용법인지 |
| `gram` | 문형표 | 4형식 전환 전치사 판정 + 직접 쓴 문항 |
| `cloze` | 그 밖 | 같은 묶음에서 오답 |

## 문항을 만들 때 지킬 것 — 답이 하나로 정해져야 한다

한때 모든 부록에 「예문의 밑줄 구간을 빈칸으로」라는 한 가지 방식을 돌려썼다가
성립하지 않는 문항을 잔뜩 만들었다. 걷어낸 이유를 남겨 둔다. **같은 함정을 다시 파지 말 것.**

1. **연결사를 한 문장만 주고 뚫으면 안 된다.**
   `[However | In addition | For example], listeners rated slower speakers as trustworthy.`
   앞 문장이 없으면 무엇을 넣어도 말이 된다. 연결사는 앞뒤 관계가 답을 정하므로
   반드시 앞 문장을 붙인다. 그래서 `conn_passages.py`의 지문 문항을 따로 썼다.

2. **오답을 같은 묶음에서 뽑으면 안 되는 곳이 있다.**
   역접 묶음 안에서 오답을 고르면 `however / nonetheless`가 같이 올라와 둘 다 정답이 된다.
   방향 라벨(`lbl`)이 붙은 묶음은 단어 시험의 오답도 다른 묶음에서 뽑는다.

3. **오답이 품사부터 다르면 문법으로 걸러져 어휘를 묻지 못한다.**
   `There were [Nor | ◆hardly | Few] any seats left` 는 Nor·Few가 애초에 그 자리에
   못 오므로 뜻을 몰라도 맞힌다.

4. **조각만 주면 오답이 어이없어진다.**
   `[per | in spite of | ◆at] the entrance` 처럼 두세 단어짜리 조각은 문제가 되지 않는다.
   전치사 지도를 용법 판정으로 바꾼 이유다.

5. **판정 문항의 보기는 서로 배타적이어야 한다.**
   문형표의 「2형식·보어는 형용사」와 「2형식·감각동사+형용사」는 둘 다 맞는 말이 된다.
   그래서 판정은 4형식 → to/for/of처럼 확실히 갈리는 자리에만 낸다.
   `as`의 「시험에서 갈리는 지점」도 다른 용법 위에 겹치므로 보기에서 뺐다.

## 손대지 않은 것

`DB.items`의 Day 배정은 시드 고정 셔플(`random.Random(20261113)`)로 40개씩 끊은
결과가 이미 각 항목의 `d`에 박혀 있다. 그 원본 스크립트는 소실됐고, 재배정하면
안 되므로 복원할 이유도 없다. 부록 1~18과 문형표·전치사 지도·as의 원본 데이터도
같은 이유로 `index.html`의 DB가 유일한 원본이다.
