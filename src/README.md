# src — 데이터 소스와 적용 스크립트

이 앱은 **빌드 파이프라인이 없다.** 저장소 루트의 `index.html` 한 파일이
소스이자 산출물이고, 모든 데이터는 그 안의 `const DB = {...}` 리터럴에 들어 있다.

예전에 파이썬 빌드 파이프라인이 있었지만 작업 컨테이너가 초기화되면서
**소스가 통째로 사라졌다.** 산출물만 남아 데이터를 역추출해야 했다.
이 폴더는 같은 일이 다시 일어나지 않게 하려고 있다.
부록 데이터와 직접 쓴 시험 문항은 여기 파이썬 모듈이 원본이다.

## 폴더

```
src/
  data/       손으로 쓴 원본 데이터 (여기를 고친다)
  apply/      data/를 읽어 index.html의 DB에 넣는 스크립트
  check.js    index.html 한 파일을 검사한다 (의존성 없음)
```

### data/

| 파일 | 내용 |
|---|---|
| `apx19_rows.py` | 부록 19 동명사·to부정사 116행, 8섹션 |
| `apx19_cz.py` | 부록 19 개념 시험 53문항 |
| `bank_a.py` | 준동사 심화 예문 36문장 |
| `bank_b.py` | 전치사에 유의할 동사 예문 34문장 |
| `bank_c.py` | 2·4·5형식 예문 25문장 |
| `neg_judge.py` | 부정어구 긍정/부정 판정 24문항 |
| `formats.py` | 부록마다 쓸 시험 형식(f)과 연결사 방향 라벨(lbl) |

### apply/

```bash
python3 src/apply/01_apx19.py     # 부록 19를 DB에 넣는다
python3 src/apply/02_formats.py   # 시험 형식·라벨·부정어구 판정 문항
python3 src/apply/03_banks.py     # 직접 쓴 예문 뱅크
node    src/check.js              # 검사
```

**세 스크립트는 몇 번을 돌려도 결과가 같다.** 이미 들어가 있으면 건너뛰거나
같은 값으로 덮어쓴다. 문장을 더 쓰고 싶으면 `data/`의 해당 파일에 줄을 보탠 뒤
그 스크립트를 다시 돌리면 된다.

## 절대 지킬 것

1. **`index.html`을 손으로 편집하지 않는다.** `apply/_db.py`로 읽어서 고치고 다시 쓴다.
2. **기존 항목의 `d`(Day)를 재배정하지 않는다.** 외우던 묶음이 전부 뒤섞인다.
   새 항목만 맨 뒤 Day에 붙인다.
3. **저장 키는 단어 문자열(`w.toLowerCase()`)이다.** 인덱스 기준으로 되돌리면
   데이터를 추가할 때마다 사용자 기록이 날아간다. 예전에 실제로 그랬다.
4. **출처를 지어내지 않는다.** 기출 번호를 확인할 수 없으면 `추가`로 둔다
   (화면에는 「본시험 대비」로 나온다).
5. **본문에 줄바꿈을 넣지 않고 곧은 따옴표만 쓴다.**

`apply/_db.py`의 `check()`가 1·2·3을 쓰기 직전에 검사한다. 통과 못 하면 저장되지 않는다.

## 시험 문항이 만들어지는 방식

부록마다 성격이 달라 생성기를 따로 뒀다. 그룹의 `f` 값이 어느 것을 쓸지 정한다.

| `f` | 어디에 | 무엇을 묻나 |
|---|---|---|
| `conn` | 연결사·부사 10묶음 | 빈칸 + 글의 방향 판정. **오답은 다른 방향 묶음에서 뽑는다** |
| `pair` | 혼동 어휘 | 한 문장에 함께 나온 두세 단어를 서로 바꿔 넣기 |
| `vprep` | 전치사에 유의할 동사 | 동사가 아니라 뒤에 붙는 전치사를 빈칸으로 |
| `neg` | 부정어구 | 긍정이냐 부정이냐 판정 |
| `form` | 준동사 | 직접 쓴 문항만 |
| `prep` | 전치사 감각 지도 | 예문의 전치사 빈칸 / 단어는 핵심 이미지 고르기 |
| `as` | as 정리 | 이 문장의 as가 어느 용법인지 |
| `gram` | 문형표 | 4형식 전환 전치사 판정 + 빈칸 |
| `cloze` | 그 밖 | 같은 묶음에서 오답 |

**같은 묶음에서 오답을 뽑으면 안 되는 곳이 있다.** 연결사는 한 묶음 안이
전부 같은 방향이라 `however / nonetheless`가 함께 보기로 오면 둘 다 정답이 된다.
판정 문항도 마찬가지여서, 이름이 서로 겹치는 자리(문형표의 2형식 셋, `as`의
「시험에서 갈리는 지점」)에는 내지 않는다.

## 손대지 않은 것

`DB.items`의 Day 배정은 시드 고정 셔플(`random.Random(20261113)`)로 40개씩 끊은
결과가 이미 각 항목의 `d`에 박혀 있다. 그 원본 스크립트는 소실됐고, 재배정하면
안 되므로 복원할 이유도 없다. 부록 1~18과 문형표·전치사 지도·as의 원본 데이터도
같은 이유로 `index.html`의 DB가 유일한 원본이다.
